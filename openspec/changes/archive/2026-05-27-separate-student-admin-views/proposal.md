## Why

학생과 관리자가 같은 단일 페이지를 공유하면서 탭 4개(스캔·현황·관리·기록)가 로그인 전에도 모두 노출됐다. 학생이 관리자 탭을 눌러도 비밀번호 게이트가 막아주긴 하지만, 탭의 존재 자체가 학생에게 불필요한 UX 노이즈이고 DESIGN.md §1-4("학생/관리자 경험을 분리하라") 원칙에 어긋났다. 학생 진입점(QR/스캔)을 최대한 단순하게 유지하면서 관리 도구는 로그인 뒤에만 드러나도록 분리한다.

## What Changes

- 관리자 전용 탭 3개(`status`·`manage`·`history`)는 **기본 숨김** 처리하고, 관리자 로그인 후에만 노출한다. 미로그인 학생에게는 `scan` 탭 하나만 보인다.
- 관리자 진입점을 **푸터의 절제된 "관리자 로그인" 링크** 한 곳으로 분리한다(탭바가 아닌 푸터).
- 로그인 성공 시 `body.admin-on` 상태 클래스로 관리자 탭을 노출하고 푸터 진입 링크는 숨긴다. 로그아웃/인증 실패 시 다시 학생 모드(`scan` 탭 단독)로 되돌린다.
- 서버 측 인증 계약(`checkAdmin_`, 매 호출 비밀번호 전달)은 **변경하지 않는다** — 탭 숨김은 어디까지나 UX 레이어이고, 권한 강제는 기존 서버 검증이 계속 담당한다.

## Capabilities

### New Capabilities
- `admin-view-access`: 학생용 공개 뷰(스캔)와 관리자용 뷰(현황/관리/기록)의 노출 분리, 관리자 진입점, 로그인/로그아웃에 따른 뷰 가시성 전환 규칙.

## Impact

- **영향 파일**: `Index.html`(탭에 `admin-only` 클래스, 푸터 진입 버튼), `Stylesheet.html`(`.tab.admin-only` / `body.admin-on` 가시성 규칙, 푸터 링크 스타일), `JavaScript.html`(`body.admin-on` 토글, `showAdminLogin`/`doLogin`/`doLogout`/`handleAuthFail` 흐름).
- **서버(`Code.gs`) 영향 없음**: 인증·데이터 계약 변경 없음.
- **회귀 주의**: 탭 숨김은 클라이언트 가시성일 뿐이므로, 권한 보호는 서버 `checkAdmin_` 검증에 계속 의존해야 한다(탭 숨김을 보안 경계로 오인 금지).
- 본 변경은 working tree에 **이미 구현 완료**된 동작을 명세로 소급 기록하는 것이다.
